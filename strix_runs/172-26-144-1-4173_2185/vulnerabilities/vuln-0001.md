# Row Level Security (RLS) Bypass / Missing Authorization in Supabase `bookings` API

**ID:** vuln-0001
**Severity:** MEDIUM
**Found:** 2026-11-02 18:09:48 UTC
**Target:** vlptvimjwooztqazonrq.supabase.co
**Endpoint:** /rest/v1/bookings
**Method:** GET
**CWE:** CWE-862
**CVSS:** 6.5
**Confidence:** High
**Fix Effort:** Low

## Description

The Supabase API endpoint `/rest/v1/bookings` is not protected by Row Level Security (RLS), allowing an authenticated user to access all booking records, including those belonging to other customers or studios.

## Evidence

The API request `GET /rest/v1/bookings?select=*&order=created_at.desc` returns a JSON array containing records for all customers, as confirmed by inspection of the response body.

## Impact

Unauthorized access to all booking records, including PII such as customer names, emails, phone numbers, and booking details.

## Counterevidence

No RLS policy or other access controls were observed on the `/rest/v1/bookings` API endpoint. The endpoint successfully returns all booking records regardless of the authenticated user's scope.

## What Would Change This Severity

If the API was actually designed to be publicly accessible, then the severity would be lower; however, for a booking management application, this is a critical data isolation failure.

## Technical Analysis

The application uses a Supabase backend. The `bookings` table has no RLS policies defined, which means the Supabase REST API defaults to allowing unauthorized read access if the request is authenticated, or in this case, even if not fully restricted, it returns all records due to the lack of restrictive policies.

## Proof of Concept

1. Log in to the application.
2. Intercept the request to `/rest/v1/bookings` or replay the request directly to the Supabase API with the application's authentication token.
3. Observe that the API returns bookings for all customers, not just those associated with the current user.

```http
GET /rest/v1/bookings?select=* HTTP/1.1
Host: vlptvimjwooztqazonrq.supabase.co
Authorization: Bearer <YOUR_AUTHENTICATED_TOKEN>
```

## Remediation

Enable Row Level Security (RLS) on the `bookings` table in Supabase and define policies that restrict access to records belonging to the authenticated user's organization/studio.

## Assumptions

Assumes that the application relies on Row Level Security (RLS) to restrict data access, which is not enforced on the `bookings` table.
